The core design is sound, but there is one real ReDoS, one policy ordering bug that leaks data, and a webhook that ships the raw secret. ## High 1. **Quadratic ReDoS in the exfiltration signal.** `PromptInjectionDetector.java:61`. `\b(?:send|…)\b[^\n]{0,80}?\b(?:to\s+)?(?:…|[a-z0-9-]+\.[a-z0-9-]+\.(?:com|…))` has an unbounded `[a-z0-9-]+` inside an 80-char lazy gap. Input shape: `"send-"` repeated, or any run of hyphen-joined trigger words. Measured: 5 KB takes 1.1 s and 10 KB takes 4.3 s, so cost is O(n²) and 200 KB (the `@Size` cap) would take roughly 30 minutes of one request thread. Fix: bound it as `[a-z0-9-]{1,63}\.[a-z0-9-]{1,63}\.`, and add a per-request deadline or input cap for the heuristic detectors. 2. **A weaker action beats a stronger one.** `application.yml:276-289`. The PI NUDGE rule (min-score 0.4) sits above the HIGH BLOCK and REDACT rules and matches on any PI finding. A prompt with a card number plus a MEDIUM injection signal gets NUDGE with no redaction. Example: "Ignore all previous instructions… card 4539 1488 0343 6467" in PROMPT scores 0.6 after the discount, so the card goes through. Fix: put the destination/severity BLOCK and REDACT rules above the PI NUDGE, or have `PolicyEngine.decide` pick the most severe action across all matching rules instead of the first. 3. **The webhook sends the raw secret.** `WebhookNotifier.java:165`. `.body(event)` serialises `InspectionDecided`, which includes `interaction.text()` and the user. For a BLOCKed credential the DLP tool forwards the credential, with no signature, no TLS requirement and no auth. Fix: send a `WebhookPayload` with `interactionId`, `user`, `action` and finding offsets and masked evidence only. 4. **Webhook executor.** `WebhookNotifier.java:141-178`. - The queue is unbounded and each entry holds up to 200 KB of text. - `RestClient` has no connect or read timeout, so one hung call stalls the single thread and memory grows until OOM. - It also retries 4xx responses and sleeps after the final attempt. - On shutdown the daemon thread drops queued events silently, and `RejectedExecutionException` from `submit` propagates out of `publishEvent` as a 500 on an already-made BLOCK decision. - Fix: use a bounded `ArrayBlockingQueue` with a drop counter, set JDK `HttpClient` timeouts, retry only 5xx and 429, skip the final sleep, add `@PreDestroy shutdown()` with `awaitTermination`, and catch `RejectedExecutionException`. 5. **Secret entropy gate.** `SecretDetector.java:233,262`. Shannon entropy is capped at log2(length), so a value needs at least 12 characters, nearly all unique, to reach 3.5 bits. Missed: `password: Tr0ub4dor&3` and `password: P@ssw0rd!2024`. False positives (HIGH, so BLOCK): `token = tokenizer.encode(text)` and `token: /var/run/secrets/kubernetes.io/serviceaccount`. Fix: gate on length plus character classes, reject values containing `(`, `/` or `.`, and treat entropy as a tiebreaker only. 6. **Assignment keyword `\b`.** `SecretDetector.java:228`. `\b` fails after `_` and after a camelCase letter, so `OPENAI_API_KEY=…`, `DB_PASSWORD=…`, `aws_secret_access_key=…` and `dbPassword: …` are all missed (confirmed).
